## 技能三十一：采样窗起点对齐——一个采样会造成 20 kHz 上百度的相位偏差

- **适用场景**：扫频相位在高频突然偏离模型 100° 以上，但低频基本正常；多次重启/多进程之间结果不一致；同一频点的幅值正常而相位像“整体转了一个角度”。
- **使用方法 / 踩坑清单**：
  1. **先算等效延迟**：对解缠后的相位残差拟合 `τ = −Δφ/(360·Δf)`。若 τ 近似常数且接近 `1/fs`，就是**整采样平移**，不是模拟电路。本项目 `fs = 100 MHz/2048 = 48828.125 Hz`，一个采样 **20.48 µs**；实测重启前后差约 **24 µs**（一个采样 + 3.5 µs 帧内偏移），在 20 kHz 正好是 **147°**（相位 = 360·f·τ）。
  2. **判断是“进程内”还是“跨进程”**：连续两次扫频（同一进程）重复性 ±0.1°，而重启后整体平移，说明进程内已对齐、跨进程未对齐。不要再用“平均多次”掩盖，平均消不掉常数相位。
  3. **RTL 对齐**：在 `top.v` 里把 `ps_start` 先锁存为 `start_pending`，等 `rx_data_valid`（I2S 帧有效）且状态机在 `IDLE` 时才真正启动：

     ```verilog
     wire start_here = start_pending && rx_data_valid && (state == IDLE);
     if (start_here) start_pending <= 0;
     else if (ps_start && state == IDLE) start_pending <= 1;
     ```

     这样启动点固定在“帧边界”，进程内重复性从“可能差一个采样”变成“稳定”。本项目改完后同进程 20 kHz 重复性 0.08°。
  4. **跨进程仍会差一个采样**：codec 的 DAC/ADC 帧相位在每次 `configure_codec + load_design` 后不一定相同。彻底解决要么把 I2S 帧计数器/codec 帧同步也纳入复位对齐，要么每次启动重测短接（见技能三十二），用当前进程的短接把相位重新锚定。
  5. **验证方法**：同一频点用“网页扫频 → 标定脚本新进程 → 网页扫频”三条路径对比原始相位；若三者一致到 0.1° 内，说明测量链稳定，问题只在“表与当前进程不匹配”。
- **失效条件**：若相位残差不是线性的（低频正常、中频突变），是滤波器/非线性，不是采样平移；若 `rx_data_valid` 本身抖动，锁存也可能锁到错误帧，需要示波器/ILA 看 I2S 帧边界。

## 技能三十二：启动参考扫频——把“当前进程的短接”自动测出来

- **适用场景**：每次重启 dashboard 后，直连校准表与当前进程的短接相位不一致，导致 20 kHz 相位错误；又不想每次手工跑 `calibrate_path.py`。
- **使用方法 / 设计规范**：
  1. **默认开启**：`run_dashboard.py` 里 `START_WITH_REFERENCE` 默认 `1`，只有显式 `START_WITH_REFERENCE=0` 才跳过；`start_dashboard.sh` 的默认值也改成 1。这样 `python3 run_dashboard.py` 直接启动就会触发。
  2. **主线程加载 PL**：pynq 的 `Overlay` 需要主线程的 asyncio loop，所以先在主线程 `_ensure_rtl_design()`（`configure_codec + load_design`），再起后台线程跑参考；否则会报 `There is no current event loop in thread 'Thread-1'`。
  3. **网页立即可用**：参考在后台跑，Flask 立即 `app.run()`；`/api/status` 返回 `reference.running`，前端把“开始扫频测量”按钮禁用并显示“正在进行相位对齐...”；`/api/start_sweep` 在参考期间返回 409 `{"status":"busy","msg":"正在进行相位对齐，请等待参考扫频完成后再试"}`。
  4. **一轮即可**：参考只扫一轮 240 点（`n_target=1000`，周期 10–410，约 20 s），不重复平均；它的目的是“相位锚点”，不是提高信噪比。
  5. **扫完才更新**：240 点先放在内存 `rows`，全部结束后才 `cal.CAL_TABLE = rows` + `save_calibration_table()`（临时文件 + `os.replace` 原子写）；中途失败（比如检测到不是短接）直接抛异常，旧表原封不动、按钮恢复。
  6. **自动 re-exec 到 venv**：系统 `python3` 没有 pynq 时，`run_dashboard.py` 顶部检测并 `os.execv` 到 `/usr/local/share/pynq-venv/bin/python3`，保证“project 目录下直接 `python3 run_dashboard.py`”也能跑。
- **失效条件**：若参考扫频本身被 DUT 挡住（不是短接），参考会按“前 5 点绝对判据”失败并保留旧表；此时要先换短接再启动。若进程在参考期间被 kill，下次启动仍需重新参考。

## 技能三十三：短接检测——绝对幅度比与“电平无关”判据的取舍

- **适用场景**：启动参考前需要判断“现在接的到底是不是短接”，避免把 DUT 当成短接写进校准表。
- **使用方法 / 踩坑清单**：
  1. **只用前 5 个频点（20–26 Hz）做绝对幅度判据**：`ratio = (mag · old_gain) / level_scale`，要求 `0.98 ~ 1.02`；串了 1 k/2.03 k/11.6 k/97.2 k 的 DUT 第一点就会以 0.916/0.844/0.486/0.100 被拦。
  2. **必须按 DAC 音量归一化**：codec 的音量 `0x402B/0x402C` 会从 `0x10`（−6 dB）变成 `0x08`（−12 dB），整体幅度差 2 倍。用 `app.py` 的 `_current_dac_volume()` 读出当前值，再和旧表 meta 里的 `dac_volume`（缺失时按 0x10）算 `level_scale = cur/old`，否则短接会被误判成 0.500。
  3. **20 Hz 相位不可靠**：20 Hz 正好在 codec 高通拐点，重启后短接自身相位会漂 3.48°；用 0.5° 门限会把短接误判。相位判据应放宽或删除，改用幅度。
  4. **20 kHz 形状判据也不可靠**：codec 高频在进程间会漂 1–2 dB，短接的 `mag(20k)/mag(20Hz)` 形状比会到 0.769（−2.2 dB），5%/20% 门限都可能误拦短接。最终方案是**只用前 5 点幅度**，20 kHz 形状判据删除。
  5. **纯电感是例外**：9.8 mH 的 DCR 仅约 12 Ω，20 Hz 的 H≈0.999，和短接只差 0.1%，前 5 点判据拦不住；这是该方法的固有限制，需要更细的绝对门限或高频判据才能区分。
- **失效条件**：若 DUT 在 20–26 Hz 的等效阻抗与短接差不到 2%（例如纯 9.8 mH），判据会放行；若 DAC 音量读数失败/为 None，`level_scale` 退回 1.0，仍可能误判。

## 技能三十四：H 平面表的“进程无关性”——短接会抵消，不要重建/旋转

- **适用场景**：每次新进程都要换一张 H 平面表，否则高频崩；怀疑“表必须和短接表配套”。
- **使用方法 / 设计规范**：
  1. **先认清公式**：`raw = S · H_true`，短接表就是 `S`，所以

     ```
     H_row = raw · 短接表 = H_true_row
     ```

     短接在表里**已经抵消**，H 平面表与“用哪张短接表建”无关，是**进程无关**的。
  2. **表崩的真正原因**：测量时用的短接表与**当前进程**不一致。`H_cal = raw · S_old = H_true · (S_cur/S_old)`，多了一个复比例，20 kHz 就偏 100° 以上。只要启动参考测出**当前进程**的短接，`H_cal = H_true`，旧表直接可用。
  3. **不要重建**：把旧表乘 `S_new/S_old` 会得到 `H_true_row · S_new/S_old`，反而把表转错（本项目 9.8 mH+11.6 k 的 20 kHz 被推到 −2.50 dB/−79°、−2.69 dB/−116°）。
  4. **不要旋转**：`apply_short_change` 再乘一次 `S_cur/S_ref` 是同一类错误（−2.70 dB/−116°）；正确做法是**什么都不做**，只保留启动参考。
  5. **验证**：短接参考 20k `5.347e-5/−86.12°` 与旧表建表短接 `5.348e-5/−86.06°` 一致时，9.8 mH+11.6 k 的 20 kHz 回到 **−6.28 dB/−3.14°**（模型 −6.28/−3.12°）。
- **失效条件**：若参考测得的是 DUT 而不是短接（前 5 点判据失效，例如纯 9.8 mH），H_cal 仍会带 DUT 的响应，表不可用；此时必须先确保接的是短接。

## 技能三十五：H 平面插值——复平面反距离加权，别用中值滤波

- **适用场景**：同一 |H| 下不同相位类型的 DUT（纯电阻 vs 容性 RC）在 6.6–6.9 kHz 出现假陷波；按幅度插值/中值滤波会破坏真实特征。
- **使用方法 / 设计规范**：
  1. **按复数 H 插值**：每条标准行存 `h_re/h_im`，在复平面算距离 `d = |H_cal − H_row|`，权重 `w = 1/(d² + 1e-6)`，加权平均 `Zin`。这样纯电阻和 RC 会各自取到相位匹配的标准行，不会在电平交叉处插错。
  2. **频率方向用 log f 线性插值**：`np.interp(log(f), log(F), row)`，240 点足够密。
  3. **不要中值滤波**：6.6–6.9 kHz 的“假陷波”是插值方式造成的，不是噪声；中值滤波会连真实谐振一起削掉。换成复平面 IDW 后陷波自然消失。
  4. **近短路保护**：`|H| > 0.999` 时直接返回原 H，避免 `Z = Zin(1-H)/H` 放大误差。
  5. **R_ref 从 97.2 kΩ 的低频 Z 取中位数**，约 10.98 kΩ；不要用标称 10 kΩ 或万用表值硬编码。
- **失效条件**：若 DUT 的 H 落在标准行覆盖不到的区域（例如很大的纯电感），IDW 只能近似；需要补标准件或改用物理模型。

## 技能三十六：标准件要用万用表值，不要用标称值

- **适用场景**：RC/RL 标准行拟合出的串联电阻与万用表差很多；曲线整体偏移。
- **使用方法 / 踩坑清单**：
  1. **先确认标准件本身**：本项目曾把 1.02 kΩ 当成 10 nF 的串联电阻，实际 DUT 并没有串 1.02 kΩ，导致 10 nF 拟合出 `R_s=1.08 kΩ` 的错误结论；换成 1.473 kΩ 实测后修正。
  2. **1.55 kΩ 实际是 15.5 kΩ**：扫频高频 −14.8 dB/−34.9° 的“异常”其实是电阻读错了一位；用万用表复核后重建。
  3. **RC 的 R 用万用表值**：10 nF+11.6 k 用 11.6 kΩ（万用表），不要用标称 11.6 k 的 ±5%；拟合容差会直接进入标准行。
  4. **RL 的 R 是“总电阻”**：9.8 mH 线圈的 DCR（约 12 Ω）+ 串联电阻，例如 9.8 mH+11.6 k 的 `Rtot=11612`；不要把 DCR 漏掉。
  5. **标准行的 `level` 用 |H| 中位数**，排序后建表；同一 DUT 重复测的 `level` 会因短接/音量轻微变化，但 H 的复形状稳定。
- **失效条件**：万用表本身精度（0.5% 级）会限制标准行精度；10 nF 电容容差（±5%~±10%）会限制 RC 行的相位精度，需要时用 LCR 表测。

## 技能三十七：直连校准表的工程化——复数、原子写、热重载、元数据

- **适用场景**：校准表被网页进程和标定脚本共享，需要可复现、可追溯、不半写。
- **使用方法 / 设计规范**：
  1. **存复数系数**：`h_re/h_im` 为主，`mag_gain/phase_offset_deg` 为人读字段；去嵌入用复数乘，幅值按对数插值、相位按增量插值，跨 ±180° 不错。
  2. **原子写**：`.tmp` + `fsync` + `os.replace`；直接 `open(path,"w")` 崩溃会留下 0 字节表，服务起不来。
  3. **热重载**：记录 `(mtime,size)`，文件变化自动重读；文件删除则清空内存表；解析失败沿用旧表并只告警一次。
  4. **元数据**：`dac_volume`、`ref_amp`、`created`、`source`、`freq_points`、`repeat`、`periods`；驱动电平变化时能告警/归一化。
  5. **原始值与校准值都落盘**：`mag_db_raw/phase_deg_raw` 与 `mag_db_cal/phase_deg_cal` 并存，加 `cal_applied` 标志；表头变更时旧 CSV 自动改名归档。
- **失效条件**：多进程同时追加历史需要文件锁或按天分文件；网络文件系统的 mtime 精度可能不够，需要内容哈希。

## 技能三十八：Flask + PYNQ 的启动顺序——PL 必须在主线程加载

- **适用场景**：dashboard 后台线程加载 PL 报 `There is no current event loop in thread`；或网页起来后第一次扫频才加载 bitstream，导致第一次测量失败。
- **使用方法 / 设计规范**：
  1. **主线程加载**：`_ensure_rtl_design()`（`acceptance.configure_codec()` + `load_design(ensure_bitstream(), 1e8)`）在 `app.run()` 之前、主线程执行；后台线程只做扫频。
  2. **Flask 单线程**：`app.run(host="0.0.0.0", port=5000, debug=False, threaded=False)`，避免多请求并发争用 MMIO/PL。
  3. **启动即参考**：参考线程 daemon 化，主线程继续 `app.run()`；网页轮询 `/api/status` 拿 `reference.running/done/error`。
  4. **venv re-exec**：系统 python 没有 pynq 时自动 `os.execv` 到 pynq venv；`XILINX_XRT=/usr` 要在 import pynq 前设置。
  5. **脚本/服务路径**：`start_dashboard.sh` 用 `sudo env XILINX_XRT=/usr ... /usr/local/share/pynq-venv/bin/python3 run_dashboard.py`；直接 `python3 run_dashboard.py` 由 re-exec 兜底。
- **失效条件**：若多个进程同时加载 bitstream/争用 `/dev/mem`，会出现 `Resource busy`；需要先 `pkill` 旧 dashboard 再启动。

## 技能三十九：板端部署与 Git 推送的取证流程

- **适用场景**：需要把 Python/JSON/XSA 部署到 PYNQ 板，并确认 GitHub 远端与本地一致。
- **使用方法 / 踩坑清单**：
  1. **文本与二进制分开传**：文本走 Jupyter contents API 的 `format=text`；XSA/二进制走 `format=base64`（`upload_bin.py`）。直接 `cat` 大文件会截断。
  2. **Jupyter 根目录不是 `/`**：`/tmp/xxx.json` 会 404；路径要写 `project/data/...`（相对 `/home/xilinx/jupyter_notebooks`）。
  3. **部署后校验 sha256**：本地/远端逐文件比对（`verify_board_files.py`），不要只看“上传成功”。
  4. **GitHub 推送**：网络不通时用 SSH 443 包装（`ssh_us.cmd`：`140.82.112.36:443` + `HostKeyAlias=ssh.github.com`）；`git push` 报 `Connection timed out` 可重试，成功后 `git ls-remote` 仍可能超时，以 push 输出为准。
  5. **GitHub API 抓取有 100 KB 截断**：`web_fetch` 的 raw/contents 大文件会被截断，校验大文件要靠本地 sha256 或分段抓取。
- **失效条件**：板端无外网/DNS 时只能走局域网 Jupyter；XSA 的 base64 上传对大小敏感，超大文件建议分块。

## 技能四十：测量排错的总原则——先分“随机/系统”，再分“硬件/软件”

- **适用场景**：扫频曲线“看起来像器件特性”，但换参数/换进程就变；或者同一 DUT 多次测量不一致。
- **使用方法 / 踩坑清单**：
  1. **同点重复性**：同一频点连续测 N 次，看幅值 cv、相位 std。cv 大 → 随机（积分窗、信噪比）；cv 小但曲线整体偏 → 系统。
  2. **参数扫描**：改变 `periods`/`N`/`dac_volume`/`start` 对齐，看结果是否单调收敛；收敛到某值说明之前是偏差。
  3. **多路径对照**：网页扫频、标定脚本新进程、网页再次扫频，三条路径比原始相位；一致 → 测量链稳定，问题在表/缓存/进程。
  4. **先短接后 DUT**：任何“高频崩”先看短接本身是否 0 dB/0°；短接不正常时不要怀疑 DUT 或算法。
  5. **一次只改一个变量**：表、短接、音量、RTL、标准件分开验证；本项目多次因为同时换了短接表和 H 平面表，把问题归错到“旋转方向”。
- **失效条件**：若 DUT 本身在漂移（温漂、接触电阻），重复性实验会把漂移误判成随机；需要先固定夹具/等待热稳定。
