# 技能包 (Skill Package)

本目录包含团队在开发“便携式电子电路智能诊断系统”过程中，沉淀下来的可复用经验与脚本。这些经验不仅适用于本项目，也可直接迁移至其他 PYNQ-Z2 或 Vivado 仿真工程中。

## 技能一：Vivado 波形显示排错指南
- **适用场景**：在 Vivado 中跑仿真时，数字信号（如正弦波、PID输出）波形显示异常（如折叠、全是方块）。
- **使用方法**：
  1. 若输出为负数（有符号数据），右键信号名 -> `Radix` -> 选择 `Signed Decimal`。
  2. 若要观察模拟包络线，右键信号名 -> `Waveform Style` -> 选择 `Analog`。
- **失效条件**：此方法仅改变仿真视图的显示方式，不改变底层硬件数据。若修改后波形仍杂乱，需排查 RTL 代码中是否发生了位宽溢出。

## 技能二：Windows 环境下 Git 权限与代理一键配置
- **适用场景**：使用 VS Code 或命令行推送代码到 GitHub 时，频繁提示 `not found`、`Permission denied` 或网络超时。
- **踩坑清单**：
  1. **网络超时**：Git 默认不走系统代理。需在终端执行 `git config --global http.proxy http://127.0.0.1:<你的加速器端口>`。
  2. **权限不足**：去 Windows 的“凭据管理器” -> “Windows 凭据”中，删除所有以 `git:https://github.com` 开头的记录，强制 Git 重新弹窗授权。
- **验证方法**：在终端运行 `git push`，看到 `Everything up-to-date` 或进度条满即可。

## 技能三：Python/Vivado 多环境与字符编码排雷指南
- **适用场景**：使用 VS Code 编写和运行 Python 脚本，或在 Vivado 中跑 Testbench 仿真时，遇到依赖库找不到、标点报错、乱码或死循环。
- **使用方法 / 踩坑清单**：
  1. **Python 模块找不到**：若 `pip install` 成功但 VS Code 报 `ModuleNotFoundError`，说明遇到了多环境冲突。在终端运行 `python -m pip install <模块名>` 强制给当前运行的 Python 安装。
  2. **代码带框/报错**：AI 生成的代码常带有中文全角逗号或不可见字符，VS Code 会高亮提示。复制后务必检查并替换为英文半角符号。
  3. **Vivado 仿真乱码**：Verilog 的 `$display` 尽量不要输出中文，防止 UTF-8 与系统 GBK 编码冲突。
  4. **Vivado 仿真死循环**：若修改了代码加了 `$finish` 仍不停，且提示 `Invalid Top Module`，说明新代码编译失败，Vivado 加载了旧快照。使用 `Flow -> Reset Behavioral Simulation` 清理缓存后重跑。

## 技能四：正交解调（I/Q Demodulation）定点化设计规范
- **适用场景**：在 FPGA 内进行交流信号（如正弦波）的幅值与相位测量，且仅有 16 位 ADC 采样精度时。
- **使用方法**：
  1. **混频（乘法）**：16位 ADC 信号与 16位本振（DDS生成的cos/sin）相乘，结果需用 32 位寄存器存储，防止溢出。
  2. **积分累加**：积分窗口为 N 个点时，需预估最大值。例如 15000 * 32767 * 1000 ≈ 4.9e11，需使用 **48位** 累加器（`reg signed [47:0]`）。
  3. **归一化**：计算最终幅度前，需将累加结果除以（N * 放大倍数）还原真实值。
- **失效条件**：若累加器位宽不足 48 位，长时间积分会导致数据高位溢出翻转，波形与计算完全错误。

## 技能五：Verilog 三段式状态机（FSM）设计规范与排雷
- **适用场景**：在 FPGA 中设计控制流程（如扫频控制、接口通信时序、按键消抖等）。
- **使用方法 / 设计规范**：
  1. **严格使用三段式**：
     - 第一段（时序逻辑 `always @(posedge clk)`）：仅负责当前状态 `state <= next_state`。
     - 第二段（组合逻辑 `always @(*)`）：使用阻塞赋值 `=`，根据当前状态和输入信号算出 `next_state`。**绝对不能用时序逻辑写第二段**，否则每个状态会多停留一个时钟周期。
     - 第三段（时序逻辑）：根据当前 `state` 输出控制信号（如 `clear`、`en`）。
  2. **单周期脉冲防叠加**：在第三段 `always` 块开头，必须默认将输出信号赋值为 0，再在 `case` 分支里拉高，确保输出的是干净的单周期脉冲，防止下游模块一直处于复位状态。
  3. **位宽防呆（钳位）**：在状态机变量计数时（如 `freq_idx`），即使位宽足够（如 8位最大 255，扫 240 个点），也务必加上 `if (cnt < MAX)` 的限制，防止状态机跑飞导致异常回绕。

  ## 技能六：Vivado 仿真环境排雷与波形调试技巧
- **适用场景**：在使用 Vivado 进行 RTL 行为级仿真时，遇到环境报错、找不到信号、或波形显示异常。
- **使用方法 / 踩坑清单**：
  1. **旧进程占用（文件无法访问）**：如果点击 Run Simulation 报错 `另一个程序正在使用此文件`（如 `simulate.log`），说明上一次仿真的后台进程（`xsimk.exe`）未退出。解决办法：在 Vivado 中点击 `Flow -> Close Simulation`，或去 Windows 任务管理器结束 `xsimk.exe`。
  2. **找不到内部模块信号**：在波形窗口试图添加 `state` 或 `shift_reg` 等内部信号时，若在顶层 `tb` 找不到，必须在左侧的 `Scope` 窗口双击实例化的 `dut`（被测模块），进入其内部层级后，才能在 `Objects` 窗口选中并拖入波形。
  3. **仿真乱码**：Testbench 中的 `$display` 或 `$fwrite` 尽量只输出纯英文和数字。中文字符极易与 Windows 系统的 GBK 编码冲突导致乱码，且不影响波形本身的正确性。
  4. **幽灵缓存（代码更新但仿真结果不变）**：若确信代码已保存，但跑出的波形/数据依然是旧的，通常是 Vivado 读取了旧的编译缓存。解决：`Flow -> Reset Behavioral Simulation`，或直接关闭 Vivado，手动删除工程目录下的 `*.sim` 文件夹后重新打开。
  5. **仿真死循环/无法停止**：如果跑仿真时进度条一直卡住不停，检查 Testbench 中是否漏写了 `$finish`，或者 `for` 循环的边界条件写死导致出不来。按下仿真窗口上方的红色正方形（Stop）强制中断即可。
- **失效条件**：此技能仅适用于仿真阶段的软件排错。如果上板（Bitstream）后硬件逻辑不对，应使用 ILA（集成逻辑分析仪）进行在线抓取波形，而非仿真。

  ## 技能七：I2S 协议发送模块（Master TX）标准实现
- **适用场景**：需要用 FPGA 向音频 DAC/Codec 芯片发送串行音频数据时。
- **核心设计规范**：
  1. **动态声道选择**：使用 `wire [15:0] active_audio = lrclk ? audio_data_L : audio_data_R;`，避免复杂的逻辑分支。
  2. **错峰更新**：通过 `bclk_fall_d` 将数据更新延迟到 `bclk` 下降沿之后的系统时钟周期，绝对避免建立/保持时间冲突。
  3. **高位寻址**：使用 `case` 语句直接通过 `bit_index` 索引 `active_audio[15-bit_index]`，绝不使用易错的移位寄存器。
- **验证方法（Self-Checking Testbench）**：在测试台中不要只看波形！在 `posedge bclk` 处，利用内部变量（如 `slot_index`）自动推算出 `expected_sdata`，并与真实的 `sdata` 比对，一旦出错立即通过 `$display` 打印 ERROR。这种验证方式在大型工程中极其高效。

## 技能八：Zynq-7000 PS+PL (AXI GPIO) 软硬件联调排雷指南
- **适用场景**：使用 PYNQ 框架，通过 Python（PS侧）控制 PL 侧自定义 IP（RTL代码）的数据读写时。
- **使用方法 / 踩坑清单**：
  1. **外部复位陷阱**：如果在 `top.v` 中使用了外部 `rst_n` 输入，但在 Block Design 中悬空，会导致芯片永远处于复位状态。**强烈建议**：在 RTL 内部写一个上电自动复位计数器（如数 255 个周期后拉高 `sys_rst_n`），彻底抛弃外部复位，避免物理按键未接导致的死锁。
  2. **位宽匹配**：48 位或 64 位的超大寄存器，不要试图在 BD 中直接连 32 位的 AXI GPIO。应在 RTL 顶层（`top.v`）直接拆分为高低位（如 Low 32 + High 16），在 BD 中分别接双通道 GPIO。
  3. **Python API 掩码**：PYNQ 新版本中，`AxiGPIO.channel.write(data, mask)` 必须带掩码，写 32 位全位时填 `0xFFFFFFFF`。
  4. **48位有符号数还原**：Python 读回高低位拼接后，`(high << 32) | low` 得到的是无符号数。必须判断是否大于 \(2^{47}\)，大于则减去 \(2^{48}\) 才能得到真实的负数（补码还原）。
- **失效条件**：上述规则适用于 Zynq-7000 系列与 PYNQ 3.x 及以上版本。若不按掩码写入，硬件寄存器将不会被修改。

## 技能九：I2S 协议接收（RX）模块 RTL 设计规范
- **适用场景**：FPGA 作为 I2S Master，需要从音频芯片（如 ADAU1761）或外部 ADC 采集串行数字音频信号时。
- **核心设计规范**：
  1. **时钟边沿检测**：因为 FPGA 是 Master，`bclk` 是由内部 100MHz 分频产生的。不用跨时钟域，直接用 `clk` 打两拍检测 `bclk` 的上升沿（`bclk_rising`）。
  2. **延迟采样与移位**：在 `bclk_rising` 脉冲到来时，将 `sdata_in` 放入移位寄存器的最低位，并左移。在 `bit_cnt == 16` 时，根据 `lrclk` 的高低电平，将 16 位移位寄存器的数据锁存到左声道或右声道。
  3. **MCLK 必须提供**：绝大多数音频 Codec 芯片（如 ADAU1761）在进入 I2S 模式前，必须有主时钟（MCLK，通常约 12.288MHz）驱动。RTL 中可通过简单的分频（如 100MHz/8 = 12.5MHz）生成并绑定到特定物理引脚（PYNQ-Z2 为 U5）。
- **失效条件**：若 `bclk` 由外部提供，需改为跨时钟域处理；若 MCLK 缺失，芯片将静音，导致采回的数据全是底噪。

- **常见排错（Vivado 专属）**：
  1. **旧进程占用**：仿真报错 `另一个程序正在使用此文件`，需点击 `Flow -> Close Simulation` 关闭旧的波形窗口，或去任务管理器杀掉 `xsimk.exe`。
  2. **找不到内部信号**：在波形窗口加信号时，若找不到 `state`，需在左侧 `Scope` 窗口双击底层的 `dut` 实例才能看到内部变量。
  3. **仿真太慢**：将 `TIME_MAX` 计时参数改小（如 10000 改为 5），以加速仿真。
- **失效条件**：如果在组合逻辑段（第二段）中使用了 `<=`，或在时序逻辑段（第一、三段）中使用了 `=`，将导致综合出的硬件存在竞争冒险或毛刺。

## 技能十一：AXI GPIO 硬件映射取证与 PS 侧驱动编写规范
- **适用场景**：在 PYNQ / Zynq 上编写 Python 驱动控制 PL 侧 AXI GPIO 外设时，需要确切的基地址、通道位宽与信号连接关系，不能靠猜。
- **使用方法 / 踩坑清单**：
  1. **不猜地址**：Vivado 导出的 `.xsa` 本质是 zip 包。解压后读取 `design_1.hwh`（IP 端口连接表）和 `design_1.bda`（地址段映射）。在 `bda` 中搜 `SEG_<IP>_Reg` 可找到 `C_BASEADDR`（如 `0x41200000`）。
  2. **寄存器偏移固定**：axi_gpio 数据寄存器偏移为 ch1=0x00、ch2=0x08，TRI 方向为 0x04/0x0C；先核对参数 `C_GPIO_WIDTH` / `C_GPIO2_WIDTH`，位宽不足时高 16 位会被截断。
  3. **48 位有符号回读**：累加器拆成“低 32 位 + 高 16 位”两个通道拼接，再按补码符号扩展成 Python 负数（`v - (1<<48) if v >= (1<<47)`）。
  4. **时序清零陷阱**：PS 把 `start` 拉低后，状态机回 IDLE 会触发 `clear` 清零累加器——取数必须在 start 仍为高电平时完成，驱动里用“启动 → 等待 → 读数 → 停止”的便捷接口规避。
- **失效条件**：直接按“常见 0x40000000”猜基地址，地址错误时 AXI 写静默失败；未核对通道位宽直接读 48 位，得到的是截断/错位数据。

## 技能十二：正交解调定点归一化与四态校准规范
- **适用场景**：把 FPGA 解调器输出的 48 位整数累加值还原为物理幅值（V）与相位（度），并对整机增益/相位偏差做系统级校准。
- **使用方法 / 设计规范**：
  1. **归一化口径唯一**：`norm_factor = N × ADC_GAIN × LO_GAIN`，`I = acc_I × 2 / norm_factor`。系数必须与 Python 定点模型**单点同步**——模型改 N，驱动必须同步修改，否则幅值系统性失真。
  2. **幅值相位公式**：`mag = hypot(I, Q)`，`phase = degrees(atan2(Q, I))`；满量程电压单独定义常量（`ADC_FULL_SCALE_V`），把归一化幅值换算成 V。
  3. **四态校准**：每个频点用 4 个已知参考态（如幅值 A_ref、相位 0/90/180/270°）实测，`mag_gain = A_ref / mean(mag)`、`phase_offset = 平均回绕相位差`。
- **失效条件**：N 与硬件实际积分窗口不一致时还原幅值系统性偏大；跳过四态校准直接读数，会带入固定的增益与相位偏差且难以排查。

## 技能十三：PYNQ-Z2 板载音频 Codec (ADAU1761) I2C 通路排雷
- **适用场景**：在 PYNQ-Z2 上自定义 PL 硬件，通过 PS 的 I2C EMIO 引脚控制 ADAU1761 进行音频收发时。
- **核心避坑指南**：
  1. **引脚错位坑**：官方手册或网上部分教程会将 Arduino 扩展口的 `P15/P16` 误标为 Codec I2C。实际上 ADAU1761 的 I2C 引脚是 `U9 (SCL)` 和 `T9 (SDA)`。如果约束到 P15/P16，I2C 会一直报 `Errno 6 (NACK)`。
  2. **缺少 iic_bidir 导致静音**：自定义 BD 时，务必在 PL 端例化一个 `iic_bidir` 模块，将 PS7 的 `I2C1_*` 6 根引脚接入，再将 `scl_io` / `sda_io` 引出为外部端口，否则加载自定义 bitstream 后 Linux 会失去对 Codec 的硬件控制权。
  3. **时钟域锁死**：ADAU1761 必须配置 PLL 才能工作。通过 I2C 写入 PLL 参数后，必须回读 `0x4002` 寄存器确保锁定，再开启核心时钟（`0x4000` 写 `0x0F`）。
- **失效条件**：若 PL 端 `au_mclk` 没有正确输出 10MHz 方波，I2C 即使配置成功，PLL 也无法锁定，ADC/DAC 无法输出有效数据。

## 技能十四：Python-PL 软硬联调的轮询时间规范
- **适用场景**：PS 侧通过 Python 操作 MMIO（如 AXI GPIO）控制 PL 状态机，并轮询 `done` 信号时。
- **核心设计规范**：
  1. **理论时间不可靠**：积分时长（如 `window_n / fs`）只是理论硬件执行时间。
  2. **开销补偿**：Python 的 `time.sleep()` 精度极差，单次 MMIO 读写也有几十微秒的延迟。`timeout` 必须给足裕量。例如，10ms 的硬件积分，超时阈值必须设为 50ms 甚至 100ms。
  3. **调试三板斧**：当 `measure_once` 超时时，不要先怀疑 RTL 代码。第一步用 `MMIO` 裸写寄存器拉高 `start`；第二步死等 50ms；第三步直接读取地址。如果裸测能读到 `done=1`，说明硬件没问题。
- **失效条件**：如果裸写 MMIO 且死等后 `done` 仍为 0，说明 RTL 状态机因缺少数据激励（如音频线未接）或时钟丢失而死锁。

## 技能十五：双后端验收脚本 (acceptance.py) 的逻辑分离
- **适用场景**：同一个软件接口既要支持官方底层库（如 PYNQ AudioLoopback），又要支持自研 FPGA 链路时。
- **设计规范**：
  1. **字典字段差异**：音频 FFT 库返回的是 `amplitude_code` / `spectral_peak`，而自研链路返回的是 `acc_i` / `acc_q`。两者的字典 Key 完全不同。
  2. **判定分离**：在 `checks` 字典中，应该用 `if backend == "rtl": checks.update(...)` 来区分判定标准。
  3. **RTL 的验收底线**：自研 RTL 链路不依赖频谱峰值，只需满足：`done == True`、`abs(acc_i)+abs(acc_q) > 阈值`（防止纯底噪）、`clock_hz == 预期` 即可 `passed: true`。
- **失效条件**：强制用 FFT 的指标去校验时域 IQ 的输出，会导致“硬件明明通了，软件却判失败”的乌龙。
