# 大模型协作记录 (Large Model Collaboration Log) — 去嵌入校准、启动参考与采样平移

这一阶段从“高频相位塌陷”开始，最后收敛到一套完整的去嵌入校准与启动参考流程。结论先行：

1. **高频的幅相塌陷是输入网络（并联电容 + 串联电感）造成的**：`Zin` 从低频 10.986 kΩ 随频率下降并相移，只做短接校准消不掉；用 5 轮/多标准件拟合出 H 平面表后，大电阻负载的 20 kHz 相位从 −35° 拉回 −3° 量级。
2. **真正卡住 20 kHz 的是“一个采样”的相位**：`fs = 48828.125 Hz`，一个采样 20.48 µs；重启进程后 I2S 帧起点差约 24 µs，在 20 kHz 就是 100°~147°。RTL 用 `start_pending + rx_data_valid` 对齐帧边界解决进程内漂移，跨进程则由启动参考重新测短接。
3. **H 平面表与“建表短接表”无关**：`H_row = raw × 短接表 = H_true_row`，短接在表里会抵消；只要启动参考测出**当前进程**的短接，旧 13 行表直接可用。重建/旋转表（乘 `S_new/S_old`、`S_cur/S_ref`）反而会把 20 kHz 推到 −2.5 dB/−116°。
4. **启动参考的工程细节**：一轮 240 点、后台线程、网页立即用、按钮禁用 + `/api/start_sweep` 409、扫完才原子替换校准表；短接检测只用前 5 点绝对幅度（按 DAC 音量归一化），20 kHz 形状判据不可靠、已删除。

## 阶段总结

这一阶段最重要的三个认知：

1. **短接在表里会抵消，H 平面表是进程无关的**。`H_row = raw × 短接表 = H_true_row`；表崩的唯一原因是“测量时用的短接表不是当前进程的短接”。因此不需要每次重建表，只需要启动参考测出当前短接。
2. **一个采样就是 147°**。`fs = 48828.125 Hz`，20.48 µs 在 20 kHz 是 147°；RTL 的 `start_pending + rx_data_valid` 解决进程内，启动参考解决跨进程。任何“高频相位整体平移”先算等效延迟，再看是不是整数采样。
3. **先分“短接/表/算法”三层，再改一个变量**。本项目多次因为同时换了短接表和 H 平面表，把“短接表不匹配”误判成“表需要重建/旋转”；最后用“旧表 + 当前参考”一次对照就回到 −6.28/−3.14°。

工程上还沉淀了两条硬规则：**校准表扫完才原子替换**（失败不污染旧表）、**标准件用万用表值**（1.55 k→15.5 k、10 nF 的 1.02 k 教训）。
