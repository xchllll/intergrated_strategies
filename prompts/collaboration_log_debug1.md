# 大模型协作记录 (Large Model Collaboration Log) — 修复音频信号通路

本阶段的目标是让"PYNQ-Z2 → ADAU1761 → 模拟环路 → ADAU1761 → FPGA"这条音频通路真正跑通：起点是扫频相位在相邻频点来回跳 180°，终点是耳机里能稳定听到 1 kHz、扫频曲线连续可复现。

**四个根因（先给结论）**：

1. **I2S 数据线方向绑反**：`sdata_o`（FPGA→Codec）与 `sdata_i`（Codec→FPGA）在 `top.xdc` 里被对调（应为 G18 / F17），ADC 采回的是错位数据。
2. **Codec PLL 始终锁不上**：`config_audio_pll` 超时，而回读"已锁定"是假象（读回的是自己刚写进去的配置）。改用 **MCLK 直通**（`0x4000 = 0x01`，旁路 PLL）后时钟才正常。
3. **耳机被静音**：`0x4023/0x4024 = 0xE5`（bit1 = 0 即 mute），且 DAC 到混音器的开关 `0x401C/0x401E = 0x00` 没有打开。
4. **采样率不匹配**：MCLK = 10 MHz 配 CONVSR = 1024 只有 9.77 kHz，而 LRCLK 是 48.83 kHz；把 MCLK 提到 25 MHz 并设 CONVSR = 512 之后两者才自洽。

## 阶段总结

这一阶段的核心不是"改代码"，而是**把一条看不见的通路拆成可分别验证的层**：数字数据流（累加器是否在变）→ 时钟（MCLK/LRCLK/fs 是否自洽）→ 模拟开关（HP 静音、混音器开关）→ 引脚映射（数据线方向）。

大模型在"寄存器地址与位的含义""加载优先级""提交链路"上提供了有效辅助；但两次关键的方向性纠错来自实测数据：**累加器不动**这一条推翻了"相位回绕"的初始假设，**重复性随频率骤降**这一条推翻了"滤波器特性"的初始假设。经验是：任何"看起来像噪声"的现象，都要先用重复性把它和"系统性偏差"分开。
