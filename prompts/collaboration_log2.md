# 大模型协作记录 (Large Model Collaboration Log) — 环境搭建、网页与 AI 模型接入

本阶段从“把代码搬到 PYNQ 板子上跑起来”开始，逐步完成网页上位机、AI 识别框架与真实硬件联调。记录保留原始轮次内容，仅补充标题、导语和阶段总结。

| 轮次 | 用户提示词 (Prompt) | 模型回答摘要 | 自我纠错 / 验证过程 |
| :--- | :--- | :--- | :--- |
| 1 | 我改了两个代码想 `git push`，但提示 `Failed to connect to github.com port 443`，网络超时，怎么解决？ | AI 判断是 Git 没有走代理。建议先在系统里查找代理端口，然后用 `git config` 全局设置 HTTP/HTTPS 代理。 | **验证**：我用 `netsh` 查不到系统代理，但在 SakuraCat 找到了 Mixed 端口 `12450`。让 AI 确认后，通过 `git config` 设置代理，成功推送。 |
| 2 | 我自己新建了一个 `diagnosis_system` 文件夹，想放进原来的协作仓库里，并且还要配置 python 环境，怎么弄？ | AI 推荐不要在外部重新 clone，而是将代码文件夹剪切到主仓库目录下，并重建 venv。 | **自我纠错/验证**：起初我想把 `.venv` 一起移过去，AI 纠正说 `.venv` 写死了绝对路径不能移。我删除了旧环境，在主仓库下重建，并通过 `.gitignore` 忽略了 `.venv`，保证了仓库干净。 |

| 5 | 环境搭好了，我想用网页画出 Bode 图，应该用什么技术栈？前端骨架怎么搭？ | AI 推荐了 Flask + 离线 Plotly.js，并给出了 `dashboard`、`templates`、`static` 的完整目录结构。 | **验证**：按照 AI 指导下载了本地 `plotly.min.js`，跑通了基于 Mock 假数据的双图（幅频/相频）渲染，网页框架初步成型。 |
| 6 | 硬件扫完会给 240 个频点的 JSON，我该怎么在网页上留出接口？ | AI 建议用 POST 接口接收硬件数据，并修改了 `app.py`，预留了 `/api/sweep/push` 路由，规范化了 `{"freqs": [], "mag_db": [], "phase_deg": []}` 的数据格式。 | **自我纠错/验证**：我之前以为降噪也要写在前面接口里，AI 纠正说底层 T1 应该处理完再发过来。我修改了逻辑，让 `app.py` 只做纯粹的数据管道。 |
| 7 | 我们需要区分“直连”和“加缓冲运放”的校准路径，网页怎么配合？ | AI 解释了四态校准的原理，并在 HTML 页面中加入了一个“启用缓冲器”的开关，后端根据开关状态去查不同的误差表。 | **验证**：网页 UI 增加了开关，并更新了前端的 fetch 请求，将开关状态 `use_buffer` 作为 payload 发给后端。 |
| 8 | 如何搭建 AI 识别框架？现在只有假数据，怎么跑通训练流程？ | AI 编写了 `features.py` 提取 13 个核心特征，用 `gen_mock.py` 造了 6 类电路的假数据，并写了 `train.py` 训练决策树和 MLP。 | **自我纠错/验证**：发现假数据准确率只有 71%，因为 RC/RL 的公式太像。AI 建议给假数据加入电感的直流电阻 (DCR) 和频率范围差异，让模型更符合物理现实。 |
| 9 | T1 发给了我们他的 `calibration.py` 和真实的 `dataset_rc_lpf.csv`，怎么接进来？ | AI 分析了 T1 的校准逻辑，让我们先做过渡：在 Windows 下直接读 CSV 画图，预留硬件接口。并引入了 `platform.system()` 来判断环境。 | **验证**：在 `app.py` 中加入环境判断。Windows 下自动读取本地 CSV 渲染；Linux (PYNQ) 下走真实硬件扫频，实现了一套代码两用。 |
| 10 | 准备把代码拷到 PYNQ 板子上联调，需要怎么物理连接和开机？ | AI 指导先将板子跳线帽设置在 SD 启动和 USB 供电。插好网线和 Type-C 线后上电，**等 DONE 灯亮起**，再用浏览器访问 `9090` 端口进入 Jupyter 终端。 | **验证**：起初 DONE 灯不亮，排查发现是 SD 卡未插紧/跳线帽接触不良。重新插拔并等待几分钟后，成功进入 Jupyter 界面。 |
| 11 | 板子怎么通过电脑连接手机热点上网？一直提示 `Destination Host Unreachable`。 | AI 指导在 Windows 里打开 ICS (Internet 连接共享) 服务，把手机热点网卡共享给以太网卡。然后在板子终端用 `sudo ifconfig` 和 `route` 配置静态 IP 和网关。 | **自我纠错/验证**：我一开始把电脑网卡改成了 `137.1` 又改回 `2.1`，导致网络错乱。最终用 `arp -a` 查不到设备后，重新对齐了电脑和板子的 IP 段（都在 `192.168.2.x`），并配置 DNS 为 `8.8.8.8`，终于 `ping` 通了外网。 |
| 12 | 在板子上运行 `python3 app.py` 提示 `No such file or directory`，怎么办？ | AI 让我检查当前路径，并教我 用 `find / -name "app.py" 2>/dev/null` 找到文件在哪。 | **验证**：发现文件全堆在 Jupyter 根目录，通过 `cd /home/xilinx/jupyter_notebooks/` 进入后，发现之前传的文件结构全散了（平铺）。AI 建议以后直接传压缩包，在终端用 `unzip` 解压，保证目录结构原汁原味。 |
| 13 | 板子上没有自带的 `scikit-learn`，尝试 pip 安装报错 `Temporary failure in name resolution` 或者连不上 GitHub。 | AI 建议先排查 DNS 配置，然后提供了一套纯 Python 脚本，直接通过 `subprocess` 调用清华源/阿里源镜像进行安装。 | **验证**：配置好 `/etc/resolv.conf` 并重启网络后，成功通过镜像源在板子上安装了 `scikit-learn`，AI 推理不再报错。 |
| 14 | 为什么在板子上跑，网页显示的 AI 结果和假数据一模一样，而且还能弹窗？ | AI 检查发现，之前的代码在 Linux 下如果调硬件失败，会“悄悄降级”跑官方音频闭环，而且抓取了错误数据。这会导致“数据造假”。 | **自我纠错/验证**：我意识到工程严谨性的重要。重构了路由，强制区分 `rtl` 自研模式和 `audio` 模式，网页端增加了来源 Badge（徽章）动态提示。 |
| 15 | Harness 审查出了 5 个“诚实性”漏洞（如状态位残留、模式乱传、每次扫频都重烧 FPGA 等），怎么修？ | AI 逐一拆解，加入了严格的白名单校验、防止每次扫频重烧 bitstream（全局标志位）、切换音频模式时强制重置 UIO 驱动，并强行拦截了 audio 模式的 AI 推理。 | **验证**：修改后，接口传非白名单参数会自动降级为 rtl。切换模式不再卡死，网页端拨动开关，右侧的校准状态也能实时刷新了。 |
| 16 | 混淆矩阵中文全是方块，而且 `train.py` 找真实数据的路径总是报错。 | AI 在 Matplotlib 中加上了中文字体配置 `SimHei`，并用绝对路径锚定 `Path(__file__).resolve()` 重写了训练脚本的路径解析。 | **验证**：重新运行训练，图片中文完美显示，且能准确找到仓库根目录下的 CSV 文件进行域外测试。 |

| 18 | 特征提取里的 `f3db` 计算错误、相位有 -180 到 180 的跳变，导致模型预测不准。 | AI 解释了对数域扫频的边界问题，在 `features.py` 中引入了 `np.unwrap()` 做相位解卷绕，并改为动态寻找“通带最大值下降 3dB”的点。 | **验证**：修改特征工程后，模型的泛化能力和鲁棒性大大增强，为后续真实数据接入打好了坚实的数学基础。 |

## 阶段总结

这一阶段的主线是“把工程从能跑到可复现、可追溯”：环境上用 venv 隔离、用镜像源装依赖、用压缩包保目录结构；网页上先 Mock 数据跑通 Plotly 渲染，再接真实硬件；AI 上先假数据跑通训练流程，再用 `platform.system()` 和 `--real` 开关防止“演示数据冒充实测”。最容易踩的坑是“悄悄降级”和“路径散落”，最后都通过白名单、来源 Badge 和绝对路径锚定解决。
