# 大模型协作记录 (Large Model Collaboration Log) — 修复数据异常与优化曲线

通路打通之后，本阶段回答两个问题：**为什么数据会异常**、**怎样把曲线做平滑**。结论先行：

1. **高频段的"滚降"有 6 dB 是假的**：20 kHz 处 periods=10 只读到 9088，随积分窗加长单调收敛到约 19000——旧数据被短窗系统性低估；真实滚降只有 2 dB。
2. **低频段的"抖动"也是短窗造成的**：20 Hz 处 periods=3 有 −0.48 dB 的系统下坠，p=16 时只剩 −0.26 dB。
3. **校准表必须能热重载**：网页进程握着旧表，"校准后"实际等于"新测量 − 旧基准"，表现为整体相位平移**整整一个采样**（20.48 µs）。

## 阶段总结

这一阶段的四类"异常"最后都归结为**同一个方法论问题**：把"噪声"和"偏差"分开。

- 高频抖动 → 先看重复性（cv），发现是 fs 不匹配；改完之后仍有 6 dB 的"滚降"→ 再看随积分窗的收敛性，发现是短窗偏差。
- 低频抖动 → 单点重复性很好，但**扫频曲线**粗糙 → 用低频小扫频单独量，才发现是 20 Hz 附近的系统下坠。
- 相位整体平移 → 先看残差是不是恒定延迟 → 再用多路径对照排除硬件 → 最后落到软件缓存。

凡是"看起来像噪声"的现象，都要用两个实验拆解：**同点重复性**（随机成分）和**参数扫描**（系统成分）。本次会话里，这两个实验各自推翻了至少一个错误假设。
